# 计算方案包：使用与部署

本次实现为新增功能。既有脚本、智训记录和租户不批量迁移，不自动替换历史计算结果。

## 操作流程

1. 新训练结束后，先点“设为最佳”，保存待转换的业务脚本。
2. 在智训页面点“转方案 / 方案管理”，选择租户及脚本，再点“将此脚本转为方案”。已有数据库脚本和仅保存在文件目录中的旧脚本均可选择。
3. 转换完成即自动启用，无需验收、再次确认差异或手动启用。智算使用转换时封存的代码和运行逻辑；继续训练不会修改该包。再次转换会自动替换同名脚本当前使用的方案。
4. 智算只显示与智训一致的脚本名称，不显示方案 ID 或摘要；结果 ZIP 也使用脚本名称和时间命名。同名方案只展示当前启用版本，原始封存包留存用于追踪。

完整性校验、租户权限、运行环境兼容性及智算上传预检仍照常执行。转换与导入不重新运行训练验收，也不伪造实测准确率。

升级启动时，已有租户同名方案中最新的待启用版本也会自动启用，前提是冻结包完整可读。历史版本及已明确停用的已发布版本不会因此被重新启用。

## 包内保存什么

多目标训练生成一份 `.py`：每个目标的业务代码以普通 Python 代码段展开，统一入口生成全部目标文件。下载和重新上传始终处理整份脚本；重新上传不会按目标拆成多个脚本或分别替换。旧版字典内嵌代码仍可执行，下载时转换为同样可编辑的单文件结构。

模板按“隔离目录 / 原文件名”归档。模板文件名可能被业务代码用于区分提交人或目标，不能改成哈希文件名。旧包可通过 `backend.solutions.repairs.repair_template_names` 生成新修复版本：保留业务代码、冻结运行代码、环境、设置和原始包，只补充保留原名的模板副本并更新模板绑定。修复版本需要替换相应方案绑定后才会生效。

| 内容 | 保存方式 |
| --- | --- |
| 业务脚本及多工作簿子脚本 | 原始代码，不自动重写 |
| 计算基础代码 | backend 中的 Python 及相关资源、excel_parser.py、aspose_init.py、split_by_banner.py |
| Excel 原生组件 | libs 中的 DLL、SO、运行配置等；不包含许可证 |
| 模板 | 按脚本代码摘要绑定模板副本，运行时从包内解析 |
| 训练资料 | 会话目录、引用的训练源文件、期望文件、规则、附件、输出等现存文件 |
| 数据库训练记录 | Script、关联 TrainingSession、TrainingMessage、TrainingIteration、关联 DataAsset 的结构化快照 |
| 旧文件式训练记录 | 原 training_result、training_info、迭代记录及可找到的训练资料 |
| 验收参考资料 | 转换时的租户/公共基础资料与租户历史结果快照 |
| 环境与校验 | Python、依赖版本、原生库摘要、.NET 环境信息、计算配置、逐文件 SHA-256、整体内容摘要 |

不导出整个数据库，不复制用户账号、组织授权、数据库连接口令、API 凭据和 Aspose 许可证。配置中已知的敏感字段会移除。代码、对话及附件是用户内容，导出前应按业务要求检查其中是否有手工写入的敏感信息。

不存在的历史资料无法凭空恢复。缺失会被列入包清单；导入也拒绝把源环境的未归档绝对路径当作目标环境文件。旧租户级训练文件可能曾被后续训练覆盖，转换时会按当时可用资料封存。

## 导入到其他环境

在智训页打开方案管理，先确定脚本所属租户，再选择目标脚本或填写新脚本名称，并选择 ZIP。方案版本归属具体脚本，同一个包可以导入同租户下的多个脚本。导入已有脚本时保留脚本 ID、名称和原有封存版本，更新可编辑代码并建立独立的修正会话；导入完成后立即启用，原同名方案不再作为当前方案。新租户勾选“创建上方填写的新租户”。管理员必须有所属组织，系统据此建立新租户授权。

方案包含完整可执行 Python 代码，导入限定管理员，并要求勾选来源可信。导入阶段只校验、保存、恢复数据库和文件；成功后自动启用，不执行包内代码进行验收。

导入不会沿用源环境的数据库主键。会话、消息、迭代、资产重新分配 ID；目标脚本使用本地已有 ID 或新建 ID。系统重建关联，并将附件路径改为本地训练会话目录。源租户名称只保留在方案来源信息中。同一脚本重复导入同一摘要返回已有方案，不重复建立训练记录；按名称导入时，同租户同名脚本会自动复用原记录并更新代码，不创建重复脚本。程序启动自动将旧租户级唯一约束迁移为租户、脚本、摘要唯一，保留历史绑定与验收状态。

导入后可直接讨论和执行修正，无需重新运行首轮训练。系统保留历史迭代，并额外建立一份明确标记的“导入方案代码”，以包内业务脚本作为当前修正起点；该记录不伪造本环境的执行结果或准确率。旧导入会话如果缺少迭代代码，读取代码时会回退到该会话或方案关联的租户内脚本。修正生成新的训练版本，封存的原方案保持不变；要用于智算，需将修正后的脚本重新转方案，新方案自动启用。

导入成功后，页面自动进入导入方案的训练会话，避免把修正提交到原来的空会话。方案列表提供“进入修正”入口；旧方案缺少会话时，会从包内脚本和资料恢复会话，无需重新训练或重新导入。没有训练历史的脚本包同样会建立修正会话。当前页面正在训练或保存附件时，保留当前操作，结束后通过“进入修正”切换。

方案 ZIP 保持原始摘要。导入后的启用状态不改写原包，导入不需要独立验收。ZIP 上限 1GB；解压总大小上限 4GB、单文件 512MB、条目 30000。禁止路径穿越、链接、加密条目和大小写重名。

## 为什么程序升级不改变方案代码

任务提交时确定方案 ID 和摘要，写入任务的 analysis_report 与运行目录的 solution.json。上传预检、保存映射、确认映射及正式计算传递同一个绑定，中途不重新寻找“最新方案”。

执行前校验完整内容摘要；独立 Python 进程用隔离模式启动，只把包内运行代码加入应用导入路径。每次执行使用私有副本，临时日志、期望文件重算等不会写回原始包。正式计算的脚本正文由工作进程从包内读取，不能被当前项目传来的新版脚本替换。

旧的三个计算接口不支持方案协议，遇到已转换并启用的脚本会要求使用智算页面新版上传入口，避免绕过冻结运行链路。

## 运行环境升级

应用 Python 代码和包内原生组件已经保存；**Python 解释器、第三方 Python 安装包和系统 .NET 运行时不随 ZIP 自动安装**。同平台、匹配环境可直接导入使用；Windows 包不能承诺直接在 Linux 上执行。

升级这些依赖前，应保留旧虚拟环境及其依赖，并保留匹配的 .NET 环境。当前环境不匹配时系统拒绝运行，不静默换用新依赖。可在部署机器的 `solution_store/runtimes.json` 登记旧解释器：

```json
{
  "环境标识（错误提示中的完整值）": "D:/retained-envs/payroll-v1/Scripts/python.exe"
}
```

此登记文件仅由部署管理员维护，不从导入包恢复。选择登记环境前仍会校验其指纹；登记路径不代表跳过检查。保留旧环境并不等于复制一个 python.exe，需要完整可运行的环境及依赖。

若要采用新版基础逻辑，使用原可编辑脚本重新转方案并自动启用。旧方案继续保留。不要覆盖已封存目录或原地修改 manifest。

代码固定不代表任何输入都能得到同一结果：上传文件、显式上传的新模板、年月、工时、租户基础资料及历史数据仍是本次业务输入。新任务创建时会另行固定该任务的基础资料及历史结果快照，后续预检、确认和计算读取同一份快照，避免任务进行期间数据更新影响结果。数据库结构和宿主通信协议也需要保持向后兼容；未来破坏性数据库迁移应先回归旧方案。

## 部署及验证

- 正常应用启动时通过现有 `Base.metadata.create_all` 新建 calculation_solutions 表。无需改写既有表或批量处理脚本。
- `solution_store` 保存不可变包，须作为持久化目录与数据库一起备份。容器升级不能丢失此目录。
- 保留部署机器自己的许可证与数据库配置。不要将带训练资料的包提交到 Git；已加入目录忽略规则。
- 首次上线在测试环境用实际租户走完整流程：转换、智算、导出、另一租户导入、智算。对照计算结果后再用于正式业务。

本次自动验证包含包完整性、目录越界、训练数据库关联恢复、租户隔离、重复导入、自动启用与同名覆盖、旧文件式脚本、多工作簿归档和独立进程代码隔离。扩展回归结果见交付说明；下述既有测试在本地环境中失败。测试使用临时 SQLite 和样本文件，未操作正式租户数据。
