# 多目标文件智训与 ZIP 交付

## 使用

1. 在智训页面选择「公式模式」或「模板模式」。目标文件支持同时选择多个 Excel。
2. 在规则附件或开始训练的消息中，用上传文件名分别说明每个文件的生成要求，例如：

   ```text
   员工明细.xlsx：按员工编号关联员工信息和工资数据，输出每名员工的补偿金明细。
   部门汇总.xlsx：按部门汇总人数和补偿金金额。
   公共规则：员工编号作为文本；合同到期日保留日期；金额保留两位小数。
   ```

3. 模板模式依次选择每个文件需要处理的 sheet；每份模板的其他内容按现有模板模式保留。
4. 智训分别生成并执行各文件的脚本，逐个与对应的目标文件对比。总体准确率按所有文件的匹配单元格数加权计算。
5. 智训「生成结果」下载为 ZIP；差异对比也独立打成 ZIP。设为最佳后，在智算中选择同一脚本并上传新的源文件即可生成交付包。
6. 智算多文件结果只提供一个 ZIP 下载，包内使用对应目标文件名。启用纯值副本时，纯值副本也放入该包。

单目标文件沿用原来的训练、结果筛选和下载方式。多目标暂限公式、模板两种模式。

## 一致性与失败处理

- 每个文件保留独立的目标结构、列格式、模板路径与代码；不同文件可有同名 sheet。
- 脚本在隔离的输出目录和变量空间内分别运行，防止默认输出文件名相互覆盖。
- 所有声明的文件都必须生成，才能发布 ZIP。缺少某个文件或任一脚本执行失败时，本次任务失败，不返回部分交付包。
- 逐个完成现有格式后处理、公式重算和公式检查后，原子写入 ZIP。
- 保持现有公式警告策略；`COMPUTE_STRICT_FORMULA_ERRORS=true` 时，任一文件有严格公式错误就阻止整个包交付。
- ZIP 只包含明确交付的工作簿及启用的纯值副本，不包含源文件、规则文件、脚本、填充报告或差异文件。
- 修改已有会话的目标文件后，需重新生成脚本再验证，旧的单文件脚本不会自动变成多文件脚本。

## 配置与部署

无需新增数据库列。使用现有 `expected_structure` JSON 保存：

```json
{
  "delivery": "zip",
  "workbooks": {
    "员工明细.xlsx": {"expected_file": "...", "sheets": {}},
    "部门汇总.xlsx": {"expected_file": "...", "sheets": {}}
  },
  "sheets": {}
}
```

顶层 sheets 的联合仅用于源数据 sheet 名保留，最终写入和验证使用各工作簿自己的结构。

新生成的多文件脚本会调用 `backend.utils.multi_workbook`，部署时必须同时发布这个新模块及本次改动的后端、前端文件。推荐构建并部署同一版本镜像，避免只替换少数文件造成接口不一致。跨环境复制模板模式脚本时，还需同步对应租户的 templates / training_chat 文件及数据库脚本配置；运行时会对每个模板单独按名称和哈希定位。

智算多文件目前复用训练时保存的各份模板，不使用单个「新模板」覆盖多个目标。

## 验证

运行 `python -m unittest backend.tests.test_multi_workbook -v`。
测试使用真实的 xlsx 读写验证多工作簿执行、样式保留和 ZIP 内容；AI 调用、原生公式计算及对比使用替身，以便在无模型服务和 Aspose/Python.NET 的环境执行。
正式验收仍需在实际部署环境，用真实规则分别完成公式模式与模板模式的智训、设为最佳及智算下载验证。
