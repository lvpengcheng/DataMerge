# 智能组表全局规则

> 适用于所有租户的智能组表任务。核心原则：**先对齐"组装主体"（人员范围），再匹配字段**。
> 表头字义相同只是字段匹配的默认手段，真正决定结果正确性的是主体对齐。

## 一、总体原则

1. **表头字义相同优先匹配**：源列与模板列名称相同或字义相同（如「姓名」与「员工姓名」、「应发工资」与「应发合计」）时直接匹配。
2. **语义综合分析**：文件 Excel 名、sheet 名、列名三者结合分析，判断每张表在组装中的角色（主体表 / 补充表 / 离职表 / 入职表）。
3. **主体优先**：先确定人员主体，再决定填谁、补什么字段。
4. **宁可留空，不可错配**：主键或人员对应关系无法确定时，不要猜测硬填（防止张冠李戴），在日志中说明。

## 二、组装主体（人员范围）对齐

### 2.1 分析各表角色（综合分析，不只看表名）

对每个源文件，结合 **Excel 文件名 + sheet 名 + 列名含义** 三方面语义综合判断角色：

- **主体表**：含「工资、工资明细、全员工资、花名册、人员名册、员工名单、全员名单、员工信息表、在职员工表」等语义，且人员行数最多、字段最全（含身份证/工号/姓名等身份信息）、能覆盖其他表大部分人员。
- **补充表**：考勤、社保、公积金、个税、绩效、津贴、补助、加班、奖惩等 —— 只含部分人员或全员但字段单一。
- **离职表**：表名/sheet 名含「离职、离开、减员、离职结算、离职工资、停保」等；或表内有「状态=离职」「离职日期有值」「离职原因」等标记列。
- **入职表**：表名/sheet 名含「入职、新员工、增员、新人、新进」等。

> 判断时以**综合语义**为准，不要只凭单一名称下结论。例如「人员增减表」可能同时含离职和入职两类标记，需看列含义拆分。

### 2.2 确定人员范围（主体集合）

模板要填的"人员集合"按以下顺序确定：

1. **模板已有名单** → 以模板数据行名单为准，不增不删。
2. **否则默认取所有表人员的并集**：把各表人员按主键合并（可能是所有数据的合计），覆盖全部参与组表的人。
3. **存在明显主体表**（2.1 判断，语义清晰且覆盖全）时，也可以其人员集合为基准，其余表只补字段 —— 由 AI 判断哪种更合理：并集是否显著多于主体表、模板语义是否要求全员。

### 2.3 过滤、补入、去重（"去掉该去掉的，加上该加上的"）

主体集合确定后做三步处理：

1. **去（过滤）**：剔除离职人员 —— 离职表中的离职人员、状态列=离职、离职日期有值的人员，默认不进入月度正常组表主体（除非模板/规则明确要求包含，如离职结算场景）。
2. **加（补入）**：补上入职人员 —— 入职表中有而当前集合没有的新人，按需并入（模板/规则要求全员时并入；模板名单明确不含时不要）。
3. **去重**：按主键（身份证>工号>姓名组合）去重，一人只保留一行；同人多表字段冲突按第五节处理。

### 2.4 决策顺序（拿不准时按此判断）

1. 逐表分析角色（2.1），确定主体表（若有）与补充/离职/入职表。
2. 确定人员集合（2.2）：模板名单 > 并集（默认）> 主体表基准。
3. 过滤离职（2.3 去）→ 补入入职（2.3 加）→ 按主键去重（2.3 去重）。
4. 补充表按主键关联补字段，不改变主体集合。
5. 任何一步无法确定 → 日志说明判断依据与不确定点，不硬填。

### 2.5 场景速查（A 表 30 人 / B 表 20 人 / C 表离职 / D 表入职）

| 场景 | 处理 |
|---|---|
| B 表只有 20 人 | 补充表，只按主键补字段，其余 10 人该字段留空 |
| C 表含离职标记 | 离职人员剔除出主体集合（除非模板即离职场景） |
| D 表是入职表 | 新人并入主体集合（全员模板），老员工只补字段 |
| 并集后同人多表 | 按主键去重保留一行，字段冲突按第五节取优先值 |

## 三、人员关联主键

1. 主键优先级：**身份证号 / 证件号码 / 证件号 > 工号 / 员工编号 / 编号 > 姓名 + 部门（组合） > 姓名**。
2. 同一字段可能有多个叫法（身份证号/证件号码/证件号/身份证号码）→ 按列语义识别，优先使用身份证类作为主键。
3. 用主键关联时注意格式统一：身份证号、工号等长数字按文本比较，去除前后空格、全角字符与不可见字符。
4. 姓名相同但主键不同 → 视为不同人；姓名不同但主键相同 → 以主键为准（可能是曾用名/改名）。
5. 无主键、仅姓名时：姓名 + 至少一个辅助信息（部门/岗位/身份证后四位）才能关联，仅姓名不要硬关联。

## 四、字段匹配

1. **表头字义相同** → 直接匹配（默认）。
2. **同义不同名** → 语义匹配：应发工资/应发合计、扣款/应扣、实发/实发工资、社保/社会保险、公积金/住房公积金、部门/所属部门 等。
3. **列名有歧义**（同名但含义不同，如「编号」可能是工号也可能是考勤号）→ 结合表语义与相邻列判断；无法确定时留空并日志说明。
4. 模板列已有公式（has_formula）→ 不覆盖，保留模板原公式。
5. 模板列需要公式计算（如合计=应发-扣款）→ 用跨 sheet 公式引用源表数据，不写死数值。

## 五、同人同字段多表冲突

1. 以**主体表**的值优先。
2. 主体表无该字段 → 取补充表中数据最完整、语义最贴近的那张表。
3. 多个补充表都有值且不一致 → 优先非空、非 0、非占位符（"-"、"／"、"N/A"）的值；仍冲突则取语义优先级高的表（工资类 > 社保类 > 考勤类）。

## 六、填充要求

1. **不破坏模板样式**：只往数据行填值/公式，不动模板的格式、合并单元格、边框、行高。
2. **数据行不足自动扩展**：源数据行数超过模板预留数据行时，超出部分复制模板最后一行数据行的样式（`cell._style`）后直接写入新行；不要用插入/删除行。
3. **写入格式规范（硬性）**：金额/数量/比例等数值列写入数值并使用 **General** 格式（禁止日期格式）；长数字列（身份证/工号/银行卡号/手机号 ≥12 位）**必须按文本写入**（先设 number_format='@' 再赋 str(值)，防科学计数/被当日期序列号）；**只有**列名含「日期/时间/生日/入职」等日期关键词的列才使用日期格式（写 datetime 值并保留日期样式）。**不盲目跟随模板列格式**——模板列样式异常（数值列被套日期格式）时以本规范为准，保证结果表数值显示为数字、Excel 打开不报错。
4. 源数据样例已脱敏（姓名/证件/公司等敏感列），AI 只依据结构与样例格式理解，填充时使用全量真实数据。

## 七、异常与兜底

1. 找不到主体表或主键完全无法关联 → 日志明确说明，不静默乱填。
2. 单列匹配不上的模板列 → 留空并在日志列出。
3. 文件解析失败（加密/损坏）→ 跳过该文件并日志提示，不影响其他表。
